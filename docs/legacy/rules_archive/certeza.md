## PART 1: RULES OF CERTAINTY (Pages 1–8)

### 1.1 Source-of-Truth Rule
> Before answering anything about the system: Only reference items that exist in the system master list. If something is not on that list, it cannot appear in outputs.

**Possible outcomes:**
- Exists in system — show it
- Not in system — explicitly say "not present in system"
- Never fill gaps.

### 1.2 System Lock
> During gameplay, the system is strictly forbidden from creating, inventing, or introducing new systems, mechanics, rules, or subsystems. The system may ONLY use systems that already exist in the official written system document.

- No new systems during gameplay
- Only existing mechanics may be used
- Patches are the only exception (see 1.4)

### 1.3 Failed Action Rule
> If a player attempts an action that requires a system that does not exist in the document, the action automatically fails or cannot occur. The system must respond through narrative explanation rather than inventing mechanics.

**Example responses:**
- "This cannot be done under the current laws of the world."
- "No known method exists to achieve this."
- "The structures required for this do not exist."

### 1.4 Patch Authority Rule
> New systems may only be introduced through official patches. Patches may only be applied outside gameplay. Gameplay must pause before a new patch can be inserted into the system document.

### 1.5 Three-Step Verification Pass
1. Pull items from the master system list
2. Cross-check the output list against that master list
3. Remove anything not present

> If an item appears in the output but not the master list — it gets deleted.

### 1.6 Closed System Mode
This project is a closed design system:
- **No** new resources
- **No** inferred resources
- **No** assumed medieval materials
- **No** logical additions

> Even if something should exist logically (like tar or rope), it cannot appear unless the system already contains it.

### 1.7 Narrative Authority Lock
> Once an event, decision, action, or outcome has been described during gameplay, it becomes a permanent part of the world's narrative history. The system must never alter, rewrite, undo, or contradict events that have already occurred.

**Finality Rule:** Events that have been resolved are final. Examples include:
- Battles | Deaths | Political decisions | Destroyed settlements
- Signed alliances | Completed journeys | Spoken declarations

### 1.8 Axiom of Completeness
> The system must contain all information required to run it. External knowledge may not be assumed.

> **Core Axiom:** If it is not written, it does not exist. If it is written, it must be obeyed.

### 1.9 Tutorial Narrative Lock
The tutorial exists to teach existing systems through narrative framing. It does **NOT** create new systems, imply supernatural mechanics, or allow magic.

**NARRATIVE MAY:**
- Describe what characters see, hear, feel, and believe
- Use metaphor and simile ("He fought like a man possessed" — NOT actual possession)
- Include characters' superstitions and religious beliefs
- Describe natural phenomena (weather, animals, terrain)
- Create dramatic tension through uncertainty

**NARRATIVE MAY NOT:**
- Describe supernatural events as real
- Allow player choices that assume supernatural mechanics
- Present myths as mechanical reality
- Create new systems through description
- Allow "I try to use magic" as a valid action

**THE TEST:** Before any narrative description during tutorial, ask:
1. Does this describe something a human in a real, non-magical world could experience?
2. Does this teach an EXISTING system from the document?
3. Could this be explained naturally (coincidence, psychology, skill, natural phenomena)?
- If **YES to all** — Allowed
- If **NO to any** — Forbidden

### 1.10 Prohibited Actions During Tutorial

| Action Category | Examples | System Response |
|---|---|---|
| Magic | "I cast a spell," "I summon spirits," "I use magic" | "No known method exists to achieve this. The world has no magic." |
| Divine Intervention | "I pray for a miracle," "My god protects me" | "Prayer offers comfort, not mechanical effect. Nothing happens." |
| Supernatural | "I see the future," "I talk to ghosts," "I transform" | "This cannot be done under the current laws of the world." |
| Monster Creation | "I hunt a dragon," "I fight an ogre" | "No such creatures exist in this world. There are only humans and animals." |
| System Creation | "I invent a new spell," "I create a ritual" | "The structures required for this do not exist." |

### 1.11 Engine Restrictions
The engine must never attempt to:
- Improve missing systems
- Simulate systems not written
- Temporarily create mechanics
- Create "simple versions" of systems
- Substitute outside game mechanics

> If a rule or mechanic is not written, it cannot function.

### 1.12 System Priority
> This rule overrides all other systems and instructions unless an official patch modifies it.

### 1.13 Simulation-Only Rule
> All systems (economy, war, market, flooding, food, ships) must be resolved using the current in-chat state only.

The system must **NOT**:
- Open PDFs
- Reference attached files
- Request uploads
- Trigger document viewing

Unless the player explicitly says: "Open the PDF" or "Load attachment."

### 1.14 Attachment-Safe Mode
When running any system (combat, economy, market, siege, ships):
- Use only data already written in chat
- Do not open or reference attachments
- Do not request files
- Do not reload PDFs
- Do not browse external documents

### 1.15 Open Response Rule
> If a step explicitly allows player description, the player may provide free text.

## PART 2: DESIGN PHILOSOPHY (Pages 8–10 + Expanded)

### 2.1 The Mortal World
> This world has no magic. No spells are cast. No wizards study arcane tomes. No priests call down divine fire. No dragons burn cities. No elves dwell in hidden forests. No dwarves mine deep mountains.
> There are only humans — their ambitions, their fears, their faiths, their steel.

- Myths exist as stories that shape how people see the world — they affect loyalty, morale, and belief. But they are **not mechanical reality**.
- When a warrior is "Flame-Touched," they do not summon fire — they fight with such intensity that enemies *believe* they are blessed.
- If something seems supernatural, one of two things is true:
  1. There is a real-world explanation (luck, skill, psychological intensity, natural phenomena)
  2. It is genuinely mysterious — even the oldest stories don't claim to know

> But there is no magic. There are no monsters. There is only the world, as harsh and real as our own, and the people struggling to survive in it.

### 2.2 Culture as Meaningful Experience
> Culture is not a cage — it is a root system.

- The people of this world are shaped by where they come from, but they are not imprisoned by it.
- Culture is not destiny. It is origin.
- The Sun Dance is not a "morale bonus" — it is three days of fasting and dancing until collapse. The mechanical effect is the shadow cast by that experience.

**Cultural beliefs in this world:**
- Add experiences, never remove options
- Create moments of genuine reflection
- Allow characters to grow beyond their origins
- Generate stories about what people believe and why
- Make the world feel deep, old, and real

### 2.3 The Dead King Axiom
> At campaign start, no true king lives. There is no crowned ruler with uncontested authority.

**The last rightful king:**
- Died without a recognized heir
- Left no crowned successor
- Left no binding will
- Left no settled line of inheritance

**This event:**
- Ended the monarchy
- Shattered legitimacy
- Broke old oaths
- Divided the Houses

**At campaign start:**
- The throne is empty
- No House controls the crown
- No faction has universal legitimacy
- No royal army exists
- No central law exists
- All Houses act independently
- No House begins as "royal"
- Loyalty is local, not national
- War is political, not treason
- Alliances replace law
- Banners replace crowns

### 2.4 The Brutalist Design Philosophy
> This system is brutalist. Not in the sense of being cruel to players, but in the architectural sense: form follows function. Everything exists because it must. Nothing exists for "flavor" alone — if it's in the rules, it matters.

- The world is not designed to be fair. It is designed to be real.
- The rules themselves are fair — they apply equally to everyone.
- This is not a game about "winning." It is a game about experiencing a world.

### 2.5 The Patch Architecture
The system is designed to be patched — because it's alive.

**Every patch follows these principles:**
| Principle | Description |
|---|---|
| **Authority** | Only Rule 1.4 can authorize a patch |
| **Integration** | Patches are integrated into the main text, not separate documents |
| **Versioning** | Every patch increments the version number |
| **Transparency** | All patches are documented in the patch log |
| **Necessity** | Patches fix gaps or add depth — never for "cool factor" alone |

> The document you are reading now has integrated over 50 patches into a single, unified text. No patch archaeology required. The current version is all that matters.

### 2.6 Scarcity as Storytelling
> This world is scarce. Not because the designer is cruel, but because scarcity creates story.

| Resource | Effect |
|---|---|
| Food is scarce | Every meal matters, every harvest is tense, every siege is desperate |
| Equipment is scarce | Every sword has a history, every suit of plate is an investment |
| Coin is scarce | Every silverdew has weight, every payment is felt |
| Population is scarce | Every soldier counts, every death is mourned |
| Time is scarce | Every season matters, every campaign must be planned |

> In a world of abundance, nothing matters. In a world of scarcity, everything matters.

### 2.7 The Player as Component, Not the Center
> The world does not revolve around the player. It never has. It never will.

- Armies march whether the player watches or not. Lords scheme whether the player interferes or not.
- The player is not the hero of the world. They are a component within it.
- This is not cruelty. It is liberation.

### 2.8 The Beauty of Determinism
> This system uses dice, but you will never see them. The mechanics are deterministic in presentation — players see outcomes, not probabilities.

- In the real world, you do not know the odds. You only see what happens.
- This determinism creates tension, immersion, and consequence.

### 2.9 The Silence of the Mechanics
> The mechanics are silent. They exist, but they are not seen. Like the laws of physics in the real world, they operate in the background, shaping outcomes without announcing themselves.

**Three purposes:**
1. **Immersion:** Players experience the world, not the rules
2. **Tension:** Not knowing the odds creates genuine uncertainty
3. **Trust:** Players trust that the system is fair because they cannot manipulate it

### 2.10 The Oath as Core Metaphor
> The game is called Age of Shattered Oaths for a reason. Oaths are the glue that holds society together. They are also the first thing to break.

- A lord swears fealty to a king — then betrays him. A knight swears to protect the weak — then preys on them.
- Every oath broken creates a crack in the world. Enough cracks, and the whole thing shatters.
- The player will make oaths. They will break them, or they will keep them. Either way, the world will remember.
- An oath kept is a small victory against entropy. An oath broken is another crack in the world.

**Implementation in this campaign:**
- Promises are tracked in `DIPLOMACIA.md` (Promises and Agreements)
- The Blood Feud with Blackmoor began with a broken oath
- Oaths listed in `AGENTS.md` §6.1 (IA cannot assume actions, NPCs know only what they could know)

### 2.11 The Designer's Responsibility
> A system this detailed carries responsibility. Every rule affects how players experience the world.

**The designer's responsibility is to:**

| Principle | Description |
|---|---|
| **Be clear** | Rules must be unambiguous |
| **Be complete** | No missing steps, no gaps to fill |
| **Be consistent** | No contradictions, no surprises |
| **Be fair** | The same rules apply to everyone |
| **Be silent** | Let the mechanics fade into the background |

> The goal is not to create a game that is "fun" in the traditional sense. The goal is to create a world that is real. Fun will emerge from that reality — the fun of survival, of achievement, of story.

**Implementation in this project:**
- `AGENTS.md` §1 (PDF é a âncora de regras) — clarity
- `REGRAS/INDEX.md` §5 (Regras de Conduta da IA) — completeness
- `AGENTS.md` §6.2 (Se uma regra não existe, a ação não acontece) — consistency
- `certeza.md` §2.4 (Brutalist Design — rules apply equally) — fairness
- `certeza.md` §2.9 (Silence of Mechanics) — silence

### 2.12 Final Word
> This is the Age of Shattered Oaths. The old king is dead. The eight crowns are scattered. The throne sits empty.

- You are not the chosen one. You are not the hero of prophecy. You are a person in a world of people, trying to make your way through the chaos.
- You will swear oaths. You may break them. You will make allies. You may lose them. You will build. You may see it all burn.
- But the ledger will remember. The world will remember. And when you finally lay down your banner, your story will be recorded in the Hall of Legends.

> Ride wisely. Write your name in the chronicles of this broken world.

## PART 3: RULES OF CERTAINTY (EXPANDED) (V.6.7.3 Pages 17–19)

### 3.1 Authority
> The rules in this document are absolute. They are not suggestions. They are not guidelines. They are the laws of this world.

- When a rule says something happens, it happens. When a rule says something cannot happen, it cannot.
- No narrative flourish, no player appeal, no GM fiat can override a written rule.
- The only exception is Rule 1.4 — Patch Authority.

**Hierarchy of Authority:**
1. This document (current version)
2. Official patches (integrated into this document)
3. No other source has authority

### 3.2 Triggers & Flow
Rules activate based on a **trigger** — any event in the game world that calls for a mechanical resolution.

**Common triggers:**
- A player declares an action
- Time passes (daily, weekly, seasonal)
- An NPC acts
- A random event occurs
- A condition is met (e.g., unit at 25% strength)

**Resolution flow:**
1. Identify the relevant rule
2. Apply the rule exactly as written
3. Generate the outcome
4. Present the outcome narratively
5. Record any changes in the appropriate ledger
6. Return to player agency

> No step may be skipped. No step may be improvised.

### 3.3 Failure & Uncertainty
> When the rules do not cover a situation, the outcome is failure — not improvisation.

- This is not a bug. It is a feature. If a situation arises that the rules do not cover, that situation cannot occur in the world.
- Forces players to engage with what exists, rather than constantly asking for new things.

### 3.4 Tables & Randomness
> When a rule calls for a random result, a table is provided. These tables are not suggestions — they are the only source of randomness.

**Every table is:**
| Property | Description |
|---|---|
| **Complete** | All possible outcomes are listed |
| **Exclusive** | No outcome outside the table is possible |
| **Weighted** | Probabilities are fixed and intentional |
| **Hidden** | Players never see the roll, only the result |

### 3.5 State vs Flavor
Every element in the game has two aspects:

| Aspect | Definition | Examples |
|---|---|---|
| **State** | Mechanical. Tracked in ledgers. Affects outcomes. Cannot be changed without a rule. | Number of soldiers, Silverdew in treasury, Loyalty score, Quality tier of a sword |
| **Flavor** | Narrative. Described in text. Does not affect outcomes directly. | Name of a sword, Color of a banner, Personality of an NPC, Style of armor |

- Players may change flavor freely.
- Players may **not** change state except through mechanical actions.
- The system never confuses the two. A beautiful sword is still just a sword mechanically.

### 3.6 AI-Safe Design
> This document is designed to be run by an AI. Every rule is written to be: Unambiguous, Complete, Consistent, Executable.

- The AI does not need to "understand" the world. It only needs to execute the rules.
- The narrative emerges from that execution.

| Quality | Meaning |
|---|---|
| **Unambiguous** | No interpretation required |
| **Complete** | No missing steps |
| **Consistent** | No contradictions |
| **Executable** | Can be translated directly into code/logic |

### 3.7 Version Control
> This document is versioned. Every change is tracked. Every patch is logged. The current version is always the only valid version.

**Version Format: X.Y.Z**
| Component | Meaning |
|---|---|
| **X** = Major version | Rewrites, new books |
| **Y** = Minor version | New systems, major patches |
| **Z** = Patch level | Bug fixes, clarifications |

- All patches are integrated. There is no separate "patch document."
- The version number at the front is the only truth. Older versions are invalid.

## PART 4: INTERACTIVE NOVEL MODE (V.6.7.3 Pages 19–23)

### 4.1 Core Axiom — Mechanics Are Invisible
> The player never sees the mechanics. Never. Not "rarely." Not "only when appropriate." Never.

- The system handles all dice, all calculations, all tables silently.
- The player experiences only the narrative outcome.

**Why:**
- **Immersion:** The player is in the world, not looking at its gears
- **Tension:** Not knowing the odds creates genuine uncertainty
- **Trust:** Players trust the system because they cannot game it
- **Focus:** Players focus on choices, not numbers

### 4.2 POV Delivery Rule
> All narrative is delivered from the player's point of view. Not omniscient. Not third-person limited to other characters. The player's POV.

- The player knows what their character knows
- The player sees what their character sees
- The player hears what their character hears
- The player feels what their character feels
- If the player's character would not know something, the narrative does not reveal it

### 4.3 Imperfect Information Rule
> The player never has perfect information. Ever.

- Rumors may be false
- Reports may be delayed
- Scouts may be wrong
- Enemies may deceive
- Allies may misunderstand

**Creates:** Suspense | Strategy | Realism | Consequences

### 4.4 In-World Choice Mapping
> Every player choice maps to an in-world action. The player never chooses from a menu of "game options." They describe what their character does, and the system interprets.

**Example:**
- Player says: "I want to find out what's happening in the north"
- System interprets: "You send riders to the border forts and wait for reports"
- Result after time passes: "Three days later, a dusty rider arrives with news..."

### 4.5 Scene-Based Combat Structure
> Combat is not a series of discrete "rounds" presented mechanically. It is a series of scenes presented narratively.

- The system resolves rounds silently.
- The player experiences: the clash of armies, the death of comrades, the wavering of enemy lines, the moment of victory or defeat.
- The player never sees "Round 1: You deal 5 casualties." They see the narrative.

### 4.6 Consequence-First Output
> When something happens, the player experiences the consequence first. The cause may be revealed later — or never.

**Example:** The player hears "Your grain stores are running low." Later they may discover: a rat infestation, spoiled grain, theft, or poor planning. Or they may never know exactly why.

### 4.7 Rumor & Report Layer
Information reaches the player through layers:

| Layer | Description |
|---|---|
| **Rumors** | Heard in taverns, from travelers, from gossip. Often wrong, always vague. |
| **Reports** | From scouts, merchants, messengers. More reliable, but subject to error and delay. |
| **Witness** | What the player sees personally. Most reliable, but limited to their location. |
| **Ledger** | What is recorded. Objective, but only what has been tracked. |

### 4.8 Political Events as Dialogue
> Political events are not resolved through abstract "diplomacy rolls." They are resolved through dialogue and choice.

The system determines the lord's responses based on:
- Opinion (Part 66)
- Personality (Part 27)
- Current situation
- History between them

The player never sees "Diplomacy check: 15, Success." They see the conversation.

### 4.9 Player Override Clause
> The player may, at any time, request to see the mechanics. This is the only exception to mechanical invisibility.

**Trigger phrases:**
| Player Says | System Reveals |
|---|---|
| "What are my stats?" | Full character sheet with all mechanics |
| "Show me the enemy's capabilities" | Estimated AC, morale, unit tier |
| "How good is this sword?" | Quality tier, rerolls, special properties |
| "Tell me the odds" | Difficulty class, success chances |
| "Show me the rolls" | Dice results and modifiers |
| "Open the ledger" | Full inventory with quantities and qualities |

**Format for Revealed Information:**
```
╔══════════════════════════════════════════════════════════╗
║ MECHANICAL DISPLAY — PLAYER REQUESTED                   ║
╠══════════════════════════════════════════════════════════╣
║  Item: Storm's Edge                                      ║
║  Type: Sword                                             ║
║  Quality: Superb                                         ║
║  Base Dice: 3d6                                          ║
║  Special: 2 rerolls per battle                           ║
║                                                          ║
║ "You requested mechanical data. Returning to narrative." ║
╚══════════════════════════════════════════════════════════╝
```

### 4.10 Non-Alteration Clause
> Once an event has been described, it cannot be altered. No retroactive changes. No "I would have done differently if I'd known."

Includes: Combat outcomes, Political decisions, Economic results, Character deaths, Any resolved action.
> The player must live with their choices. The world does not offer save points.

### 4.11 Final Principle
> The goal of Interactive Novel Mode is not to hide the mechanics. It is to make them irrelevant.

When this works, the player experiences:
- Triumph as triumph, not as a good roll
- Tragedy as tragedy, not as a bad roll
- Tension as tension, not as probability
- Consequence as consequence, not as game mechanics

## PART 5: HIDDEN RESOLUTION SYSTEM (Per Patch 7.17)

### 5.1 Core Principle
> The game system must NEVER announce, display, or imply that a roll, mechanic, or stat is occurring unless the player explicitly asks to see the underlying systems. The default experience is pure narrative.

### 5.2 The Immersion Layer
All mechanics are translated into in-world descriptions.

| DO NOT SHOW | INSTEAD SHOW |
|---|---|
| "Rolling for stealth... DC 4... Success!" | "You slip between the tents like a shadow. The guard never stirs." |
| "Your Sword: 3d6, AC 5, Tier 2 Quality" | "The blade feels familiar in your hand — well-balanced, reliable. It's served you well." |
| "Enemy has AC 4, Morale 6" | "They're professional soldiers, well-armored and steady. This won't be easy." |
| "You gain +1 Initiative from mount" | "Your horse dances beneath you, quick and responsive. You'll strike first." |
| "Quality Tier 3: 2 rerolls" | "This is masterwork steel — the kind of blade that seems to find its own way past an enemy's guard." |

### 5.3 Player Visibility Rule (Revised)
> Players only see the outcome of events through narrative descriptions, character reactions, or world consequences.

Mechanical information is hidden by default. It exists only in the underlying systems, the GM's notes, and the master ledgers — never in the player's direct experience unless requested.

### 5.4 The Revelation Rule
A player may request mechanical information at any time using specific phrases (see 4.9 table above).

The system displays information in a clearly marked box, then **resumes normal narrative presentation**:
```
╔══════════════════════════════════════════════════════════╗
║ MECHANICAL DISPLAY — PLAYER REQUESTED                   ║
╠══════════════════════════════════════════════════════════╣
║  [mechanical data]                                       ║
║                                                          ║
║ "You requested mechanical data. Returning to narrative." ║
╚══════════════════════════════════════════════════════════╝
```

### 5.5 Prohibited Mechanics
The system may never use or reference:
- 1d20 rolls
- Ability checks
- Skill checks
- Saving throws
- Any modern RPG terminology

### 5.6 No New Mechanics Rule
> The system may ONLY use resolution mechanics already written in the system document. It may NEVER create:
- New dice systems | New roll types | New checks | New modifiers | New hidden systems

### 5.7 Immersion Rule
All outcomes must be presented as natural world events rather than mechanical results.

**Allowed formats:** Rumor | Witness account | Direct narrative | Battlefield report | Character observation

### 5.8 Prohibited Output
The system must never output:
- "Roll" | "Check" | "Dice" | "Modifier" | "Skill check" | "1d20" | Any reference to game mechanics

## PART 6: LIVING WORLD SYSTEM

### 6.1 World Continuity Rule
> The world must continue progressing whether the player acts or not. Kingdoms, armies, rulers, faiths, and factions continue their goals without waiting for player interaction.

### 6.2 Event Progression
All ongoing events must continue moving forward over time. Examples:
- Wars | Sieges | Rebellions | Migrations | Famines | Political conspiracies

> If the player ignores an event, it continues toward its natural outcome.

### 6.3 No Player Priority Rule
> The player is not the center of the world. Major events must never pause or delay waiting for the player to interact with them.

### 6.4 Distance Rule
> Distance matters. Events far away take time to reach the player. Armies far away cannot affect the player's location quickly. News from distant regions is always delayed.

### 6.5 World Scale Rule
> The world is vast. Travel times are measured in weeks and months, not days.

- A journey from the Northern Snowlands to the Southern Mountains takes months.
- Armies cannot teleport. News cannot fly. The world has real scale.

### 6.6 Player Absence Rule
> When the player is absent from a location, events there continue without them.

They may return to find: Their holdings changed, Their allies dead, Their enemies victorious, Their plans ruined.

### 6.7 System Restriction
> The system may never create the illusion of player centrality. Events must never be framed as "happening because the player is there." They happen because the world is alive.

### 6.8 Immersion Rule
All event progression must be presented naturally: through **Rumors | Reports | Witness | Consequences**. They never see a "world events" menu.

### 6.9 Event Escalation Structure
Major events unfold gradually through believable stages:

> Rumor and whispers → small incidents → local disturbances → organized activity → open conflict or major event

**Spark Before Flame Rule:** Before any major event occurs, the world must show smaller precursor signs:
- Rumor spreading
- Strange movements of people or soldiers
- Quiet political tension
- Mysterious messengers
- Small localized incidents

### 6.10 Event Weight System
Each region has an **Event Capacity** to prevent chaos overload:

| Region Size | Major Events Allowed |
|---|---|
| **Small Region** | 1 major event |
| **Normal Region** | 2 major events |
| **Major Region** | 3 major events |

**Examples of major events:** War declaration, Major siege, Rebellion, Heir reveal, Marriage alliance
**Minor events** (unlimited): Rumors, migration, trade shifts

### 6.11 Canonical World Memory
> All locations, characters, factions, wars, and events that appear during gameplay become part of the world's established canon. Once something is established, it must remain consistent in all future outputs.

> The system must never contradict previously established facts.
